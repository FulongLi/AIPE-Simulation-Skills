# Architecture

The repository has two layers that share one [tool policy](tool-policy.md): procedural agent skills and an
executable Python package.

## Procedural skills

Thirteen skill folders (`pe-*/`), each with `SKILL.md` (the workflow), `references/` (tool-specific
procedures and checklists, loaded on demand) and `agents/openai.yaml` (UI metadata). `skills.json` is the
sidecar catalogue: access class (`open_source`, `free_proprietary`, `commercial`, `mixed`,
`target-dependent`), maturity, required tools, external-licence flag, open alternative, limitations, inputs
and outputs. `scripts/update_readme.py` and `scripts/validate_skills.py` keep the README and the catalogue
consistent ([development.md](development.md)).

## Executable package `aipe_simulation`

Installed with `python -m pip install -e .`; entry point `aipe-sim`.

| Module | Responsibility |
| --- | --- |
| `aipe_simulation.ngspice` (`locate.py`, `runner.py`, `rawfile.py`) | locate ngspice (PATH, `AIPE_NGSPICE`, `AIPE_TOOLS_DIR`, portable Windows builds), qualify it with an RC step-response test, run batch netlists and parse raw files |
| `aipe_simulation.dab` (`spec.py`, `gating.py`, `netlist.py`, `run.py`) | typed `DabCircuitSpec` (SI units), single-phase-shift gate timing for all eight switches, ngspice netlists for the ideal (Level 1) and behavioural (Level 2) dual-active-bridge models, and an end-to-end runner writing netlist, log, raw data, HDF5 waveforms and `summary.json` |
| `aipe_simulation.waveforms` (`dataset.py`, `steady_state.py`, `metrics.py`, `dab_analysis.py`, `plots.py`) | solver-independent waveform dataset (HDF5 with units and provenance), periodic steady-state identification, RMS/peak/power metrics, per-switch turn-off currents and ZVS conditions, volt-second balance, capacitor drift and an energy balance |
| `aipe_simulation.control` (`plant.py`, `controllers.py`, `sps_modulator.py`, `simulate.py`, `verify.py`, `ztf.py`) | host-side digital single-phase-shift control baseline: cycle-averaged plant, loop design, closed-loop simulation with HDF5 traces, verification against ngspice Level 1 runs ([specification](dab-sps-control-spec.md)) |
| `aipe_simulation.cli` | the `aipe-sim` command line below |

The executed 10 kW DAB benchmark and the numerical lessons behind the models are documented in
[dab-models.md](dab-models.md). Manufacturer device models (Level 3) are not executed.

## Command-line interface

```text
aipe-sim doctor                       locate and numerically qualify ngspice
aipe-sim dab default-spec             print the default Level 1 specification (YAML)
aipe-sim dab netlist --spec FILE      print the generated ngspice netlist
aipe-sim dab run --spec FILE --out D  execute the experiment and write the run directory
aipe-sim dab analyse --run D          recompute summary.json from a stored run
aipe-sim control design               design the SPS voltage/current loops and print coefficients and margins
aipe-sim control simulate --out D     closed-loop host simulation (JSON, HDF5 traces, figures)
aipe-sim control verify --out D       compare the cycle-averaged plant with ngspice Level 1 runs
```

Run directories (`--out`) contain the netlist, the ngspice log, raw data, `waveforms.h5` and
`summary.json`; they are regenerated by the CLI and git-ignored under `runs/`.
